# 可视化地图编辑器设计

日期：2026-10-12。扩展已有黑房弹球游戏，用户已选择可视化编辑器方案；执行方式沿用本会话直接实现。

## 目标

普通玩家无需修改代码即可制作地图，保存到自己的浏览器，导出文件分享。房主在准备阶段加载地图后，所有成员看到相同场地，并继续使用现有服务端权威物理和计分规则。

首版提供矩形平台（旋转后可成为斜坡）、八个出生点、固定竞技场边界。不加入任意多边形、动态机关、材质编辑、背景图片、脚本、账号或公开地图市场。地图内容只包含结构化数据。

## 编辑与使用流程

1. 首页新增「地图工坊」入口；房间准备页的房主可打开工坊。编辑时保留房间连接，其他玩家继续等待。
2. 新建地图以起点站的副本开始，也可复制任何内置地图或加载已保存地图；原内置地图不可被覆盖。
3. 编辑器采用左侧工具栏、中央网格画布、右侧属性面板。显示地图名、平台数量、八个编号出生点、校验结果和保存状态。
4. 点击选择平台，拖动移动，通过尺寸手柄缩放；属性面板可精确输入位置、宽高和旋转角度。支持新增、复制、删除平台，方向键微调与 Delete 删除；输入框获得焦点时快捷键不干扰文本编辑。
5. 八个出生点固定存在，允许选择和拖动，不能删除；编号表示玩家加入顺序对应的出生位置。
6. 默认启用 10 单位网格吸附，可关闭；提供撤销、重做，最多保留 50 次操作。一次拖动只产生一条历史，选择操作不产生历史。
7. 提供「试跑」：编辑器内使用与服务端一致的物理逻辑，操控第一出生点的圆球，支持重置和返回编辑。试跑不修改编辑数据，不创建联机比赛，不产生比分。
8. 校验通过后可保存、导出或应用到房间。无效草稿可继续编辑，不能覆盖有效存档、导出或应用；错误指明具体平台或出生点。
9. 返回首页、加载其他地图、关闭编辑器前，如果有未保存修改，提供继续编辑、保存后离开或放弃修改的明确选择。房间断线时仍能保存本地作品，但不能应用到房间。

## 本地保存与文件分享

- 地图名修剪首尾空白后为 1–40 个 Unicode 字符，描述为 0–120 个字符，按纯文本显示。
- 地图库使用独立版本键保存于 localStorage，最多 20 张。每张地图有本地 ID、名称和修改时间；允许重名但使用 ID 区分。加载后保存更新当前副本，「另存为」生成新 ID，删除需要确认。
- 保存失败（配额不足、存储不可用）显示错误并保留内存中的编辑状态，不能显示虚假的保存成功。删除或打开地图库时不盲目覆盖其他窗口保存的作品；保存前重新读取地图库，对同一 ID 的更新冲突提示另存为。
- JSON 导出采用 `{format:"blackroom-map",version:1,map:{name,subtitle,platforms,spawns}}`，使用下载文件分享；导入通过文件选择器读取 UTF-8 JSON。
- 导入文件最多 32 KiB，拒绝未知格式、版本或字段。导入地图创建新副本，不覆盖同名存档；地图文件不包含脚本或资源 URL。
- 读取旧存档时校验单条记录。损坏记录显示提示但不阻止其他有效地图使用；整个库无法解析时保留原始数据，提供导出备份和显式重置，不静默清空。
- 本地地图不跨设备自动同步；清理浏览器数据会删除地图，界面提示使用 JSON 导出备份。

## 地图模型与校验

复用现有 `MapDefinition` 的几何模型。用户文件和网络消息不信任自带的内部地图 ID 或淘汰边界，内部 ID 与固定边界由应用生成。

- 地图包含 1–64 个平台，恰好八个出生点。所有数字必须有限，不接受字符串数字、NaN 或 Infinity。
- 平台宽度为 20–1200、高度为 10–400，角度存储为弧度，限定在 −π 至 π；属性面板显示角度。平台旋转后的全部顶点必须位于编辑区域 `x:0–1200,y:0–800`。
- 出生点圆球半径沿用游戏的 20，完整圆球须在编辑区域内；出生点之间不能重叠，且不能与任何旋转平台相交。
- 淘汰边界固定为现有 `left:-100,right:1300,top:-400,bottom:900`，编辑器显示场地和掉落区，用户不能通过文件把边界扩大到异常范围。
- 允许平台相互连接或重叠；不要求地图左右对称。几何校验不保证公平或所有出生点下方都有落脚处，界面明确建议试跑检查；玩家可以设计有挑战性的跳跃地图。
- 同一共享校验器用于本地保存、导入和服务端应用。服务器对收到的数据重新校验并复制为自己的不可由客户端直接修改的地图快照。

## 联机同步与权限

- 新增房主消息 `applyCustomMap`，携带版本化地图内容；仅房主且房间处于 `lobby` 时接受。访客、倒计时、比赛中及结算状态都不能修改地图。
- 房间状态增加完整的当前地图定义（包括内置地图），客户端渲染和比赛启动都使用服务端确认的数据，避免只同步 `mapId` 导致其他浏览器找不到本地地图。
- 应用成功后广播地图名、平台和出生点；已有成员即时更新，后来加入者收到相同定义。内置地图选择保留，切回内置地图替换当前自定义地图。
- 应用失败保留原地图并返回明确错误。客户端应用后等待服务端确认，不提前把编辑草稿当作房间已启用地图。
- 地图上传消息允许最大 32 KiB，其余应用消息仍限制 4 KiB；所有连接保留每秒 60 条总限流，地图提交额外限制为每连接每秒一次。最大帧大小调整后，服务端仍逐类型检查消息字节数。
- 服务端仅保存每个房间当前地图，不建设全局地图仓库。房主离开后地图留在房间，新房主可继续使用；房间清空或服务重启时随房间销毁。
- 客户端每次收到地图切换时清空旧快照插值，不将旧地图或上一轮坐标混入新场地。

## 实现边界

将编辑状态与历史、几何变换与校验、本地地图库、文件导入导出、画布交互和界面各自拆分。编辑器复用地图绘制与坐标变换，试跑复用不含网络依赖的物理模拟，服务端继续独立决定实际联机结果。

游戏按键监听与编辑器工具快捷键互斥，关闭编辑器或试跑时清理事件监听、动画帧和输入。窗口失焦或指针取消结束当前拖动并清理按键；坐标转换兼容画布缩放与设备像素比。

保持现有中文深色界面风格，桌面鼠标和键盘为主。Docker 仍为单服务，不新增数据库、外部凭据或网络依赖。开发沿用当前隔离检出，保存阶段性 Git 提交；既有推送授权用于本次完成后的 `work` 分支普通推送，不强制推送。

## 验收

1. 单元测试覆盖旋转矩形命中与坐标换算、尺寸/角度/边界、平台和出生点相交、非法数值、数量限制、撤销重做、拖动合并及存档冲突/损坏/配额异常。
2. 文件测试验证有效导出再导入、超大文件、未知版本、额外字段、非 JSON、重名地图及原始存档保护。
3. 真实 WebSocket 测试覆盖房主应用、访客拒绝、比赛中拒绝、地图同步与后加入同步、房间隔离、地图提交限流、消息长度限制及无效地图不替换原地图。
4. 浏览器实际拖拽、缩放、旋转平台并移动出生点，撤销重做，试跑，保存与刷新恢复，导出再导入；双窗口加入同房间，确认双方看到相同自定义地图并可以操作、碰撞和计分。
5. 运行全部既有测试、类型检查、生产构建和 Docker 浏览器验收，检查首页、工坊、错误提示及真实对局截图。
6. 更新 README 的制作、分享、加载和存储限制说明；记录通过、失败或未执行的验证。独立审查后按既有流程提交并普通推送。

## 设计自审

地图文件和房间生命周期区分明确；本地存储不承诺云同步，几何合法性不承诺公平性。所有接受路径使用一致的规则，网络帧扩容不放宽普通输入消息限制。既有冠军离开导致结算姓名空白的问题不属于本次地图编辑功能范围，仍保留原交付记录。
